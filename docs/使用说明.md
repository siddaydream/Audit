# 服务业经营主体贷款贴息审核助手（subsidy-audit）

本地离线运行的贷款贴息审核辅助工具：把每期审核的人工工作量压缩为**只给新增企业填写预警通/企查查四列**，其余的匹配、沿用、比对、初判、出表全部自动完成。

> ⚠️ 本工具是**辅助初判**：结论为"是"（不符合，涉及贷款退回）与"不确定"的行，必须人工复核后定稿。终审权在人。

## 安装

```bash
pip install -r requirements.txt     # 仅依赖 openpyxl；Python 3.10+，Windows/Linux/macOS，零网络请求
```

## 工作流程（三步）

```
第1步（自动）  python run.py prefill --current 本期表.xlsx --prev 上期产出.xlsx
   输出：中间表（老企业四列已回填，新增企业空白黄色高亮）+ 新增企业清单（只读）+ .carry.json（沿用数据，勿删）

第2步（人工）  在中间表中仅为新增企业的空白四列填入预警通/企查查数据，保存
   四列 = 国标行业（预警通）、经营范围（企查查）、企查查行业、国标行业（企查查）

第3步（自动）  python run.py audit --current 中间表.xlsx
   输出（均在 output/ 目录，YYYYMMDD 日期前缀）：
   · 审核结果表（原表 + 审核结果/审核理由两列）
   · 不确定复核清单（含复核要点与换借据再报预警）
   · 关键词命中明细（供修订关键词字典）
   · 证据日志 CSV（逐行可溯源）
   本期产出可用于下一期 --prev（沿用结论前见下方列名限制）
```

## 第一步的表格要求（当前版本）

使用第一张工作表：第 1 行表名，第 2 行列名，第 3 行起为数据。

- 上期表：为回填企业信息，保留 `国标行业（预警通）`、`经营范围（企查查）`、`企查查行业`、`国标行业（企查查）` 四列及内容。缺失信息需在中间表补齐。
- 上期结论与理由：可保留、非必需。程序目前识别含 `是否发现存在不符合贴息条件情况` 的结论列和含 `简要描述审核发现的问题` 的理由列。结论为“是/否”，且借据号、数据日期、借款人名称、经营主体名称一致时，直接沿用结论；理由不参与判定。“是”表示发现不符合贴息条件情况。
- 本期原始表：不需要平台四列。当前程序总会追加四列，已有同名列会造成重复，读取时又取第一列匹配项，因此预填应使用未附加平台四列的原始表。
- 中间表：人工补齐黄色空白单元格后审核；同名 `.carry.json` 保存上期结论，请与中间表一起保留，不要单独改名或移动。

**已知限制：** 程序新增的 `审核结果（是否发现不符合贴息条件情况）` 和 `审核理由` 列名与上期读取规则不一致。直接将输出表作为上期表时，新增结论列不会被识别；若原表另有旧结论列，可能读取的是旧结论。需要沿用时，请在上期表副本中把最终确认的结论/理由填入上述可识别的列，并确保没有重复匹配的旧列。当前引擎优先沿用历史“是/否”，不会先用平台冲突重新判定。

## 在另一台电脑使用

1. 从 GitHub 下载 ZIP 并完整解压，或克隆仓库。
2. 安装 Python 3.10 或更新版本（图形界面还需要 Tkinter；Windows 官方安装器通常包含）。
3. 仓库已包含 `data/` 下五份参考文件和登记清单，下载并解压即可使用，无需另行复制参考库。两份大型明细以分块保存，首次审核时自动还原并校验。每期业务表格按需另行准备。
4. 在项目目录打开终端，Windows 运行：

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe gui.py
```

macOS/Linux 可使用 `python3 -m venv .venv`，然后将上述解释器路径换成 `.venv/bin/python`。macOS 的 `.app` 不能在 Windows 直接运行；源码可跨平台运行。

## 数据准备（首次）

本仓库已包含以下五份参考文件及 `manifest.json`，首次下载无需补文件或重新登记。更新参考库时，替换 `data/` 中对应文件，然后重新登记：

| 角色 | 文件识别关键词 | 更新频率 |
|---|---|---|
| 绿色能效明细 ×2 | 文件名含"绿色能效"，保持 `-1` / `-2` 后缀 | 按快照 |
| 环保关键名单 | 文件名含"环保关键名单"（读"总名单1017"表） | 按快照 |
| 政策审核要求 | 文件名含"政策审核要求" | 极少 |
| 国民经济行业分类注释 | 文件名含"国民经济行业分类" | 基本不变 |

```bash
python run.py init-data     # 扫描 data/ 生成 manifest.json（登记文件名与哈希）
```

参考库不需要每期重新提供；收到新快照时替换文件后重跑一次 `init-data` 即可。审核时加 `--strict` 可校验文件是否被意外改动。

**参考库分发范围**：五份参考文件经授权随本仓库分发。每期业务输入表和审核产出仍不上传。

## 判定口径

依据《政策审核要求》三步：① 国民经济行业与经营范围对照目录（来源：预警通/企查查）；② 绿色经营线索（来源：绿色能效明细）；③ 环保关键名单。目录码为 7721–7729、7461、7820、2666，排除码（如 4620 污水处理及其再生利用）与经营范围关键词字典见 `config/`，**改配置不改代码**。

判定优先级：

- **P1 沿用**：借据号命中上期"是/否"结论且数据日期/借款人/经营主体一致 → 直接沿用，理由简写"上一期判X"；
- **P2 冲突复核**：未沿用上期结论时，行业目录码与排除码等证据冲突 → 不确定，报人工；
- **P3 证据判定**：新增借据按证据矩阵判定（行业目录内 / 经营范围明确涉及 → 否；行业不在目录、经营范围不涉及、无环境类绿色线索且不在名单 → 是；其余 → 不确定）。

## 项目结构

```
run.py            命令行入口（init-data / prefill / audit）
src/              归一化、匹配、预填、证据采集、判定引擎、理由生成、输出
config/           目录码、排除码、经营范围关键词字典（可维护）
data/             参考库（五份文件 + manifest.json，随仓库分发）
input/ output/    每期投入与产出
tests/            单元测试（合成数据，不含真实业务数据）
```
